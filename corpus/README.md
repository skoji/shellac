# shellac corpus

This directory holds the PDF corpus used by the `verify` crate to exercise
incremental-save round-trips against a range of real-world PDF structures.

## Layout

```
corpus/
├── fixtures/     committed source-of-truth PDFs (S1, S2, S4, S5, S7)
├── generators/   scripts that produce the remaining samples (S3, S8..S12)
└── README.md     this file
```

### Committed fixtures vs. CI-generated samples

Six of the eleven corpus samples are generated on demand rather than
committed (see the table below). The numbering also skips S6 — that
identifier is unassigned and no such sample exists.

| Sample | Origin |
|---|---|
| S1, S2, S4, S5, S7 | committed under `corpus/fixtures/` |
| S3 | generated by `corpus/generators/generate_s3.sh` |
| S8 | generated by `corpus/generators/generate_s8.sh` |
| S9, S10, S11, S12 | generated by `corpus/generators/generate_encrypted_fixtures.sh` |

S3 and S8..S12 are excluded from `fixtures/` via `corpus/fixtures/.gitignore`
and are meant to be regenerated on demand (CI does this on every run; a local
run needs to do it once). S7 is 42 MB, which is under GitHub's soft push
warning and the 100 MB hard limit, so it is committed as a plain blob — no
Git LFS is used anywhere in this corpus.

### Regenerating the CI-generated samples

```sh
# S3: rendered-then-OCR'd scanned book, page 1 has no text layer
bash corpus/generators/generate_s3.sh corpus/fixtures 10

# S8: S1 rotated 90 degrees
bash corpus/generators/generate_s8.sh corpus/fixtures

# S9..S12: four encrypted derivatives of S1
bash corpus/generators/generate_encrypted_fixtures.sh corpus/fixtures
```

`generate_s3.sh` needs `img2pdf`, `ocrmypdf`, and `tesseract` (with the `jpn`
language pack) on `PATH`, plus a Python interpreter with Pillow (see the
script's header comment for the `S3_PYTHON` / `S3_FONT` overrides).
`generate_s8.sh` and `generate_encrypted_fixtures.sh` need only `qpdf`. All
three scripts are idempotent: they skip a target that already exists, so a
repeated run (or a CI matrix re-run) does not redo the work or clobber a
hand-curated variant.

## Sample characteristics

| Sample | Description |
|---|---|
| S1 | Vertical (tategaki) Japanese text, 1 page, linearized (Fast Web View). `%%EOF` appears twice — this is a linearization artifact, not an incremental-save artifact: the file has a `/Linearized` dictionary and two cross-reference streams, one for the first-page-only view and one for the full file. Cross-references use the **xref-stream** format. Carries both `HiddenVertOCR` and `HiddenHorzOCR` invisible OCR text layers (Acrobat Paper Capture output). |
| S2 | Horizontal (yokogaki) Japanese text, 5 pages, `%%EOF`=1, not linearized. Each page has its own `HiddenHorzOCR` invisible text layer. Cross-references use the xref-stream format. |
| S3 | Synthetic scanned-book look-alike: page 1 is a cover image (title/author rendered as pixels, deliberately excluded from OCR) and pages 2..N are horizontal Japanese body text with a Tesseract-generated invisible text layer. Page 1 having no text anchor is a deliberate, structurally-guaranteed property — it exercises the C11 "no anchor on this page" skip path in the harness. Not a derivative of S1; built from scratch by `generate_s3.sh`. |
| S4 | S2 with two PDFKit append-mode incremental saves layered on top. See "S4 provenance" below. |
| S5 | S1 opened and saved once through PDFKit's full-rewrite path (`PDFDocument.write(to:)`, no append-mode option). `%%EOF`=1 (the rewrite collapses S1's linearization-derived `%%EOF`=2 down to one). Cross-references use the **classic table-based** format (`xref` keyword + `trailer` dictionary) — this is the corpus's only classic-xref sample, deliberately pairing with S1's xref-stream format so both cross-reference formats are covered. The OCR text layer does not survive the rewrite (PDFKit does not preserve invisible-text Form XObjects it doesn't understand), so pdftotext output is effectively empty; a single seed Highlight annotation, added by `scripts/generate_s5.swift` immediately before the save, is present. |
| S7 | Large scanned book (English), 46 pages, ~42 MB, `%%EOF`=1, not linearized. Plain WinAnsi Type1 base-14 fonts (no CID/hidden-OCR layers, unlike S1/S2/S3 — this reflects a difference in Acrobat Paper Capture's font strategy between CJK and Latin text, not a structural defect). |
| S8 | S1 rotated 90 degrees via `qpdf --rotate=+90` (`/Rotate 90`, MediaBox unchanged). Exercises the rotation-aware coordinate transform. |
| S9 | S1 re-encrypted: RC4 R3 (128-bit), empty user password, owner password set. |
| S10 | S1 re-encrypted: AESV3 R6 (256-bit), empty user password, owner password set. |
| S11 | S1 re-encrypted: AESV3 R6 (256-bit), non-empty (required) user password. |
| S12 | S1 re-encrypted: AESV3 R6 (256-bit), empty user password, but `/P` clears the annotate/modify bits (`qpdf --annotate=n --modify=none`). |

### Cross-reference format coverage

The S1 family (S1 and everything derived from it — S8, S9, S10, S11, S12) uses
the **xref-stream** format inherited from S1. S5 is the one sample that
exercises the **classic xref-table** format instead, because PDFKit's
full-rewrite save path emits a plain `xref`/`trailer` structure rather than a
cross-reference stream. Between them, S1 and S5 give the harness coverage of
both PDF cross-reference styles.

## Provenance and rights

All literary source text in this corpus is in the public domain.

- **S1** is derived from *Night on the Galactic Railroad* (「銀河鉄道の夜」)
  by Miyazawa Kenji (宮沢賢治), sourced from Aozora Bunko
  (https://www.aozora.gr.jp/), a public-domain text.
- **S2 and S3** are derived from *Kokoro* (「こころ」) by Natsume Soseki
  (夏目漱石), also sourced from Aozora Bunko, public domain.
- **S7** is derived from *The Odyssey*, translated by Samuel Butler, sourced
  from Project Gutenberg (https://www.gutenberg.org/ebooks/1727, ebook #1727),
  public domain. S7 does **not** include the Project Gutenberg license
  boilerplate header/footer — the extracted text begins at the preface and
  ends mid-body, with no Gutenberg trademark or licensing text present
  (verified by grepping the extracted text for "gutenberg", case-insensitive:
  zero matches).

### S4 provenance and verifiable invariants

S4 is produced by taking S2 and applying two PDFKit append-mode incremental
saves on top of it. The generator used to build S4 is not part of this
repository — it is a macOS-only tool that relies on the PDFKit SPI write
option `PDFDocumentWriteOption_UseAppendMode` (`_kPDFDocumentWriteOption_UseAppendMode`),
which is exported by the PDFKit framework but not declared in any public
header. Because it depends on undocumented API, the generator is kept out of
this OSS repository; only its output (the S4 fixture itself) is published
here.

This means S4's provenance cannot be re-derived from a script in this repo,
but its defining structural properties are fully public-API-verifiable with
`qpdf` alone — anyone can audit them without needing PDFKit or the private
generator:

- **S2 is a true byte prefix of S4.** The leading bytes of S4, up to the size
  of S2, are byte-for-byte identical to S2, and S4 is strictly larger:

  ```sh
  wc -c < corpus/fixtures/S2.pdf                                # note the size, e.g. N
  dd if=corpus/fixtures/S4.pdf of=/tmp/s4-prefix.pdf bs=1 count=N
  cmp corpus/fixtures/S2.pdf /tmp/s4-prefix.pdf                  # exit 0 = identical
  ```

- **`%%EOF` appears 3 times** (`grep -ac '%%EOF' corpus/fixtures/S4.pdf`): S2
  itself contributes one, and each of the two append-mode saves adds one
  more.
- **Four annotations, one of each type**, added across the two incremental
  saves: `Highlight`, `Underline`, `Text`, and `Popup` (the `Popup` is the
  PDFKit-managed popup window for the `Text` annotation). This can be
  confirmed with:

  ```sh
  qpdf --qdf --object-streams=disable corpus/fixtures/S4.pdf - \
    | grep -a '/Subtype */\(Highlight\|Underline\|Text\|Popup\)'
  ```

`qpdf --check` reports no syntax or stream-encoding errors on S4.
